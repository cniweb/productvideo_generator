# Codebase Structure

**Analysis Date:** 2026-02-24

## Directory Layout

```
[project-root]/
├── .github/              # GitHub automation and workflows
├── .planning/            # Planning outputs (codebase maps)
├── finished_videos/      # Default output folder for generated artifacts
├── tests/                # Pytest suite
├── productvideo_generator.py  # Main pipeline script
├── requirements.txt      # Python dependencies
├── run.sh                # Run script for local usage
├── setup.sh              # Setup script for venv and deps
├── ci.sh                 # Local CI wrapper
└── README.md             # Project overview and usage
```

## Directory Purposes

**.github/**
- Purpose: CI configuration and GitHub metadata.
- Contains: GitHub Actions workflow in `.github/workflows/ci.yml`.
- Key files: `.github/workflows/ci.yml`.

**.planning/**
- Purpose: Planning artifacts generated by mapping tools.
- Contains: Codebase docs in `.planning/codebase/`.
- Key files: `.planning/codebase/ARCHITECTURE.md`, `.planning/codebase/STRUCTURE.md`.

**finished_videos/**
- Purpose: Output directory for generated videos/scripts/metadata.
- Contains: `*.mp4`, `*_script.txt`, `*_meta.json` artifacts referenced in `README.md`.
- Key files: (Generated outputs only).

**tests/**
- Purpose: Automated tests for the generator.
- Contains: Pytest module `tests/test_productvideo_generator.py`.
- Key files: `tests/test_productvideo_generator.py`.

## Key File Locations

**Entry Points:**
- `productvideo_generator.py`: Main runtime entry point with `__main__` block.
- `run.sh`: Shell wrapper that validates `.env`, sets up venv, and runs the script.

**Configuration:**
- `.env.example`: Template for required environment variables (do not read `.env`).
- `productvideo_generator.py`: Config loading and validation in `_initialize_config`.
- `requirements.txt`: Python dependencies list.

**Core Logic:**
- `productvideo_generator.py`: Full pipeline (trends → script → video → metadata).

**Testing:**
- `tests/test_productvideo_generator.py`: Pytest tests with dummy clients and env setup.

## Naming Conventions

**Files:**
- Snake-case for scripts and tests: `productvideo_generator.py`, `test_productvideo_generator.py`.
- Shell helpers use `.sh`: `run.sh`, `setup.sh`, `ci.sh`.

**Directories:**
- Lowercase with underscores as needed: `finished_videos/`, `tests/`, `.planning/`.

## Where to Add New Code

**New Feature:**
- Primary code: `productvideo_generator.py` (single-module architecture).
- Tests: `tests/test_productvideo_generator.py`.

**New Component/Module:**
- Implementation: Add a new module at project root (e.g., `video_generation.py`) and import into `productvideo_generator.py`.

**Utilities:**
- Shared helpers: Add to `productvideo_generator.py` or a new `utils.py` at project root.

## Special Directories

**.venv/**
- Purpose: Local virtual environment used by `run.sh` and `setup.sh`.
- Generated: Yes.
- Committed: No.

**.pytest_cache/** and **.ruff_cache/**
- Purpose: Tool caches for pytest and Ruff.
- Generated: Yes.
- Committed: No.

**.git/**
- Purpose: Git metadata.
- Generated: Yes.
- Committed: No.
